The companion project for this guide is called *Telos* - a minimal Rust kernel skeleton targeting x86-64.
Getting it to build requires configuring a nightly Rust toolchain and a small amount of Cargo plumbing; this section walks through both.

=== Nix

If you have the Nix package manager available, a flake is provided that handles toolchain provisioning, image assembly, and QEMU invocation automatically.
Setting up Nix itself is outside the scope of this guide; see https://nixos.org for more information.

[source,sh]
----
nix run               # build everything and launch QEMU
nix build .#kernel    # build kernel only
nix build .#loader    # build loader only
nix build .#bootimage # assemble the boot image
nix develop           # enter a shell with the correct toolchain
----

The below section ellaborates on the manual setup of the toolchain and environment if Nix is not used.

=== Toolchain

Because Telos builds the standard library from source and relies on an unstable Cargo feature (`-Zjson-target-spec`), a nightly toolchain is required.
The `rust-src` component provides the library source that `build-std` compiles, and the `x86_64-unknown-uefi` target is needed for the loader.

[source,sh]
----
rustup toolchain install nightly
rustup component add rust-src --toolchain nightly
rustup target add x86_64-unknown-uefi --toolchain nightly
----

=== Project Structure

Telos starts of as a Cargo workspace with two members: `loader`, which runs under UEFI before handing off to the kernel, and `kernel`, which runs on bare metal afterwards.

[source]
----
telos/
├── .cargo/config.toml
├── Cargo.toml
├── kernel/
│   ├── Cargo.toml
│   ├── linker.ld
│   ├── src/main.rs
│   └── x86_64-unknown-telos.json
└── loader/
    ├── Cargo.toml
    └── src/main.rs
----

The loader is a minimal UEFI application:

[source,rust]
----
#![no_main]
#![no_std]

use uefi::{entry, Status};

extern crate alloc;

#[entry]
fn main() -> Status {
    todo!("loader here :)")
}
----

The kernel has no runtime underneath it, so it defines its own entry point and panic handler explicitly:

[source,rust]
----
#![no_std]
#![no_main]

use core::panic::PanicInfo;

#[unsafe(no_mangle)]
pub extern "sysv64" fn _start() -> ! {
    loop {}
}

#[panic_handler]
fn panic(_info: &PanicInfo) -> ! {
    loop {}
}
----

=== Cargo Configuration

`.cargo/config.toml` tells Cargo to rebuild the core standard library crates from source rather than using a precompiled target sysroot.
This is necessary because neither `x86_64-unknown-uefi` nor the custom kernel target ships a prebuilt `core`:

[source,toml]
----
[unstable]
build-std = ["core", "compiler_builtins", "alloc", "panic_abort"]
build-std-features = ["compiler-builtins-mem"]
----

With that in place, the two crates can be built independently.
The loader targets the standard UEFI triple; the kernel uses a custom target spec that is required kernel execution:

[source,sh]
----
cargo +nightly build -p loader --target x86_64-unknown-uefi
cargo +nightly build -p kernel -Zjson-target-spec --target kernel/x86_64-unknown-telos.json
----

=== Boot Image

UEFI firmware boots from a FAT32 partition and looks for a loader at the well-known path `/efi/boot/bootx64.efi`.
The kernel is placed at `/kernel.elf` in the root, where the loader will find it at runtime:

[source,sh]
----
truncate -s 33M boot.img
mkfs.fat -F 32 boot.img
mmd -i boot.img ::/efi ::/efi/boot
mcopy -i boot.img target/x86_64-unknown-uefi/debug/loader.efi ::/efi/boot/bootx64.efi
mcopy -i boot.img target/x86_64-unknown-telos/debug/kernel.elf ::/kernel.elf
----

=== Running with QEMU

QEMU can emulate a UEFI machine when given an OVMF firmware image.
`OVMF_CODE.fd` and `OVMF_VARS.fd` are typically available through your distribution's OVMF package:

[source,sh]
----
qemu-system-x86_64 \
  -drive if=pflash,format=raw,readonly=on,file=OVMF_CODE.fd \
  -drive if=pflash,format=raw,readonly=on,file=OVMF_VARS.fd \
  -drive format=raw,file=boot.img \
  -serial file:stdio.log \
  -d int -D qemu.log \
  -no-reboot \
  -m 512M
----

Serial output lands in `stdio.log`; interrupt and exception logs go to `qemu.log`.
