=== Toolchain

Telos requires a nightly Rust toolchain with the `rust-src` component (needed for `build-std`) and the `x86_64-unknown-uefi` target for the loader.

[source,sh]
----
rustup toolchain install nightly
rustup component add rust-src --toolchain nightly
rustup target add x86_64-unknown-uefi --toolchain nightly
----

The workspace is split into two crates — `loader` and `kernel` — each built for a different target:

[source]
----
telos/
├── .cargo/config.toml
├── Cargo.toml
├── kernel/
│   ├── Cargo.toml
│   ├── linker.ld
│   ├── src/main.rs
│   └── x86_64-unknown-telos.json
└── loader/
    ├── Cargo.toml
    └── src/main.rs
----

The loader is a minimal UEFI application:

[source,rust]
----
#![no_main]
#![no_std]

use uefi::{entry, Status};

extern crate alloc;

#[entry]
fn main() -> Status {
    todo!("loader here :)")
}
----

The kernel entry point uses the `sysv64` calling convention and must never return:

[source,rust]
----
#![no_std]
#![no_main]

use core::panic::PanicInfo;

#[unsafe(no_mangle)]
pub extern "sysv64" fn _start() -> ! {
    loop {}
}

#[panic_handler]
fn panic(_info: &PanicInfo) -> ! {
    loop {}
}
----

The `.cargo/config.toml` instructs cargo to rebuild the standard library from source:

[source,toml]
----
[unstable]
build-std = ["core", "compiler_builtins", "alloc", "panic_abort"]
build-std-features = ["compiler-builtins-mem"]
----

Building the loader targets the standard UEFI triple; the kernel uses a custom target that disables the red zone, floating-point registers, and position-independent code — all requirements for bare-metal kernel execution:

[source,sh]
----
cargo +nightly build -p loader --target x86_64-unknown-uefi
cargo +nightly build -p kernel -Zjson-target-spec --target kernel/x86_64-unknown-telos.json
----

=== Boot Image

The firmware expects a FAT32 disk image with the loader placed at `/efi/boot/bootx64.efi` (the default UEFI boot path) and the kernel at `/kernel.elf`.

[source,sh]
----
truncate -s 33M boot.img
mkfs.fat -F 32 boot.img
mmd -i boot.img ::/efi ::/efi/boot
mcopy -i boot.img target/x86_64-unknown-uefi/debug/loader.efi ::/efi/boot/bootx64.efi
mcopy -i boot.img target/x86_64-unknown-telos/debug/kernel.elf ::/kernel.elf
----

=== Running with QEMU

QEMU needs OVMF to emulate UEFI firmware. Obtain `OVMF_CODE.fd` and `OVMF_VARS.fd` from your distribution's OVMF package, then:

[source,sh]
----
qemu-system-x86_64 \
  -drive if=pflash,format=raw,readonly=on,file=OVMF_CODE.fd \
  -drive if=pflash,format=raw,readonly=on,file=OVMF_VARS.fd \
  -drive format=raw,file=boot.img \
  -serial file:stdio.log \
  -d int -D qemu.log \
  -no-reboot \
  -m 512M
----

Serial output is written to `stdio.log`; interrupt logs go to `qemu.log`.

=== Nix

A Nix flake is provided that handles the full build and run pipeline automatically — toolchain, image creation, and QEMU invocation.
This is outside the scope of this document; see https://nixos.org for more information.

[source,sh]
----
nix run              # build and launch QEMU
nix build .#kernel   # build kernel only
nix build .#loader   # build loader only
nix build .#bootimage
nix develop # enter shell with correct toolchains installed
----
