The boot protocol is the contract between the loader and the kernel.
It defines both the machine state at `_start` and the data that the loader passes to it.
Keeping this contract project-specific lets Telos expose exactly the information its kernel needs without adding a dependency on an existing multiboot standard.

At a high level, the bootloader has to:

. discover the framebuffer and other firmware-provided resources;
. read and validate the kernel ELF image;
. allocate physical frames and load its segments;
. construct the kernel's virtual address space;
. capture the final UEFI memory map and leave boot services; and
. pass the boot information to `_start` using an agreed calling convention.

=== Higher-Half Kernel

Telos places the kernel in the higher half of the virtual address space.
The linker script of the kernel uses an offset of `0xffff_ffff_8000_0000` and a physical load base of `0x0010_0000`, giving the first kernel address as `0xffff_ffff_8010_0000`.
This keeps kernel addresses separate from the lower address range that can later be assigned to user programs, while allowing the physical kernel image to occupy ordinary low memory during boot. This is a common choice in kernel development as it can also enable some optimizations.
